# Data cards

В курсовой используются две трассы Alibaba: PAI 2020 — основная
(главы 3–4, приложение A), v2023 — только для проверки реализации FGD
(приложение B).

---

## 1. Alibaba PAI v2020 (основная трасса)

**Источник:** `github.com/alibaba/clusterdata` → `cluster-trace-gpu-v2020`.
Лицензия CC BY 4.0; Weng et al., NSDI'22. Скачивание и контрольные суммы —
`data/trace-gpu-v2020/README.md`, `fetch.sh`, `SHA256SUMS`.

**Таблицы:** `pai_job_table`, `pai_task_table`, `pai_machine_spec`
(без заголовков; имена колонок — из соседних `.header`).
`pai_instance_table` не используется.

**Реконструкция (`src/fgdg2/datasets/pai.py`):**

- одна задача (task) = один ганг из `inst_num` одинаковых воркеров;
  ганг — задача с `inst_num ≥ 2`;
- запрос GPU на воркера = `plan_gpu / 100`; воркер целый, если
  `plan_gpu` кратно 100, дробный, если `0 < plan_gpu < 100`;
- **дробные ганги сохраняются** (фильтр `--mixed`): дробные и целые
  ганги и одиночные задачи размещает одна и та же проверяемая политика;
- отбрасываются: задачи без GPU, комбинированные запросы (150, 250),
  задачи без времени подачи, воркеры больше максимального узла домена;
- время поступления — время подачи задачи (`job.start_time`);
- CPU = `plan_cpu × 10` милли-ядер; память в прогонщике не используется;
- тип GPU — жёсткий домен, каждый домен проигрывается отдельно.

Состав трассы после фильтра — `results/aggregates/mixed/pai_trace_stats.csv`
(`make pai-trace-stats`, claims N38–N39, таблица приложения A): ганги дают
79.4% GPU-спроса, дробные ганги — 51.9% GPU-спроса гангов.

**Блоки (`scripts/make_pai_blocks.py --mixed --load 1.2`):** поток каждого
домена режется на подряд идущие блоки; блок набирает задачи, пока их запрос
GPU не достигнет 1.2 ёмкости домена, и проигрывается с пустого кластера.
Блоки покрывают все задачи домена, выбрать «удобные» нельзя. Домены
MISC, V100, V100M32 — 778 блоков. Контроль P100/T4 (раздел 4.4) использует
блоки, где групповые задачи только целые, а дробные одиночные ставит FGD
как фон (`experiments/pai/run_pai_l1_v2.sh`, стадия core).

**Что не утверждаем:**

- в трассе нет флага «всё-или-ничего»; `inst_num > 1` — ближайший сигнал;
- `gpu_type` — назначенный тип, а не записанный запрос;
- размещение `instance → machine` по `pai_instance_table` не сверялось;
- задачи в блоке не завершаются: измеряется упаковка, а не ожидание.

## 2. Alibaba cluster-trace-gpu-v2023 (проверка FGD)

**Источник:** `github.com/alibaba/clusterdata` → `cluster-trace-gpu-v2023`.
Лицензия: research/study use only. Файлы — `data/trace-gpu-v2023/csv/`.

**Состав:** 1213 GPU-узлов, 6212 GPU, 8152 pod'а (1088 без GPU); класс
задачи = `(cpu_milli, gpu_demand)`; M усекается на 95% массы и
нормируется.

**Роль:** повтор эксперимента авторов FGD (задачи по одной, без гангов),
`make v2023`. Входные CSV совпадают по MD5 с копиями в репозитории авторов;
`data/reference/analysis_allo_discrete.csv` — их кэш результатов
(Apache-2.0).
