# Задача распределения GPU-ресурсов в кластерах для ML-нагрузки — репозиторий курсовой

Код, данные и агрегаты курсовой. Симулятор `fgdg2` размещает задачи и ганги
(распределённые задачи из k воркеров, всё-или-ничего; воркеры целые или
дробные) на GPU-кластере и считает фрагментацию по мере FGD
(Weng et al., ATC'23). Метод работы — **DP-FGD**: весь ганг размещается за
один шаг динамическим программированием по узлам поверх меры FGD; выбор карты
внутри узла жадный. Оценка — на полной gang-нагрузке трассы Alibaba PAI 2020
(778 блоков, домены MISC, V100, V100M32).

Главные числа (реестр `results/claims.csv`, строки N01–N55):

- DP-FGD против BestFit: −5.95 п.п. нераспределённой ёмкости (−47%);
- DP-FGD против последовательного FGD: −1.32 п.п. (−17%), во всех трёх доменах;
- около 73% этой разницы дают дробные ганги (эксперимент F1, раздел 4.2.1).

## Быстрый старт

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev,viz]"
make test          # тесты, в т.ч. DP против полного перебора (целые и дробные воркеры)
make figs-mixed    # claims + рисунки + таблицы глав 3–4 из готовых агрегатов
make latex-sync    # копировать рисунки и таблицы в ../latex_coursework
```

`make figs-mixed` не требует сырой трассы и занимает секунды. Полное
воспроизведение (скачать трассу → блоки → прогоны → агрегаты) — `REPRODUCE.md`.

## Структура

```
src/fgdg2/          симулятор: core (узлы, мера FGD, DP), policies, sim, datasets, workload
tests/              тесты; DP-FGD сверяется с перебором в test_gang_dp.py, test_gang_frac.py
scripts/            преобразование трассы, прогоны, сбор агрегатов, рисунки и таблицы
  make_pai_blocks.py      трасса PAI -> блоки (--mixed: с дробными гангами)
  calibrate_gang.py       одна ячейка: блок x политика x M
  run_mixed.sh            основной прогон главы 4 (12 вариантов x 778 блоков)
  run_f1.sh, derive_variants.py   F1: варианты с расщеплёнными гангами (раздел 4.2.1)
  collect_*_cells.py      сырые summary.csv -> results/aggregates/
  make_mixed_{stats,figs,tables}.py   claims N*, рисунки, таблицы
  pai_trace_stats.py      состав трассы (приложение A)
  calibrate.py, compare_reference.py  проверка FGD на v2023 (приложение B)
experiments/pai/    старые блоки с целыми групповыми задачами (контроль P100/T4, раздел 4.4)
data/               малые данные и инструкции по загрузке PAI 2020
results/            агрегаты, claims.csv, рисунки, таблицы (см. results/README.md)
docs/               описание данных; docs/prereg/ — предрегистрации прогонов
```

## Политики

| Имя в коде | В тексте |
|---|---|
| `dp` | DP-FGD (совместное размещение ганга) |
| `seq_fgd` | FGD-посл. (воркеры ганга по одному, мера FGD) |
| `atomic_bestfit` | BestFit (по воркеру, всё-или-ничего) |
| `atomic_firstfit`, `atomic_bestfit_gpu`, `atomic_dotprod`, `atomic_packing`, `atomic_random` | прочие эвристики |

## Что не утверждается

- DP-FGD точен по раскладу ганга между узлами при жадном выборе карты внутри
  узла и только для одного решения; глобально оптимальным он не является.
- Дробные ганги — не наше открытие; они объясняют, когда совместное
  размещение важно.
- Блоки проигрываются без завершения задач: измеряется упаковка, а не время
  ожидания.
